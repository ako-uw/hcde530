# MP2 Reflection

## What did you build?
CritLens is an AI-powered heuristic evaluation tool that analyzes a website URL or screenshot and returns a structured findings report based on Nielsen's 10 Usability Heuristics. A designer pastes a URL or uploads a screenshot, clicks Evaluate, and receives a prioritized list of UX issues with severity ratings (0-4), descriptions of where each problem appears on the page, and actionable recommendations. The tool is built for UX designers who want structured feedback before a critique session, and for design managers who review work for quality and consistency. It is deployed at https://critlens-ai-review.lovable.app/

## What decisions did you make?
CritLens sits at the intersection of Design and Research tracks. The interface is the product — a designer interacts with it directly — but the primary output is a structured findings report, which is characteristic of a Research track tool. I kept Lovable as the platform because it had a built-in AI gateway that worked without an external API key — Bolt required an external key for real computation. The biggest scope decision was removing the overall numeric score and replacing it with a stats panel showing heuristic counts and severity distribution, after discovering the AI was assigning fabricated scores to heuristics it could not observe. I also added 5 integrity rules that prevent the tool from mapping infrastructure behavior to UX findings. On the UI side, the design went through around six iterations — starting with a dark mode version, then a basic layout, then researching current UI trends and best practices, before arriving at the final minimalist typographic direction that the tool uses today.

## What would you do differently?
I would add visual analysis for URL inputs using a headless browser like Puppeteer, which would take a screenshot of the page before sending it to the AI. The technical complexity here is significant — it requires a backend server, browser automation, and additional latency — which is why I proceeded with the simpler HTML text approach for this project. The current URL analysis misses visual issues entirely, including color contrast, typography problems, and layout issues. The second thing I would change is building the mutually exclusive input tabs earlier. They were added late in the process, and the early version allowed a user to technically submit both URL and screenshot at the same time.

## What does this work demonstrate?
This project demonstrates C1 through the iterative building process — the tool went through at least six distinct versions before reaching the deployed state, each responding to a specific problem I identified in the output or interface. It demonstrates C7 most clearly through the integrity rules: I identified that the AI was fabricating confidence on heuristics it had no evidence for, and I restructured the output to only report what was actually observed. The Methodology page documents this openly. It demonstrates C8 through a deployed tool with a public URL, a clear scope, honest documentation of limitations, and a reflection that accounts for what I would change.
